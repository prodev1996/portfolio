# Rajiv Bhandari / Portfolio

A personal portfolio for software development, application support, and data work. Built with Next.js App Router, React, TypeScript, Tailwind v4, Framer Motion, and Lenis.

## Run locally

```sh
npm install
npm run dev
```

Open http://localhost:3000. Production checks:

```sh
npm run lint
npx tsc --noEmit --incremental false
npm run build
```

## Content and design

- `data/projects.ts`: project facts, screenshots, case-study content, and external links.
- `data/project-presentation.ts`: concise display titles, categories, and gallery descriptions.
- `data/site.ts`: contact details and résumé PDF.
- `data/experience.ts`, `data/education.ts`, `data/certifications.ts`: résumé content.
- `app/globals.css`: responsive design tokens, themes, typography, and motion.
- `DESIGN.md`: design direction, audit, and research references.

The homepage prioritizes four projects and links to two additional studies. All six original case-study routes and the résumé route remain available. The skills, experience, and credentials anchors resolve within the shorter background section.

Bricolage Grotesque and Manrope are self-hosted through next/font. The portrait and project screenshots are original portfolio assets. The social card and favicon are generated by Next.js image routes.

## Writing and publishing

The Writing section lives at `/writing`, with a two-article preview on the homepage. Fourteen researched articles cover new AI systems and risks, chips, phones, laptops, software releases, security, data, and observability. Each article links to primary sources and separates vendor claims from the author's analysis.

### Write an article locally

1. Run `npm run dev` and open `http://localhost:3000/keystatic`.
2. Choose **Articles → Add**. Enter a title, short summary, category, and publication date. New articles default to **Draft**.
3. Write in the visual editor. It supports headings, links, lists, tables, code blocks, images, and a separate source list. Use descriptive alternative text for images.
4. Save, then open `/writing` to find the local draft-preview link. Drafts are excluded from public article routes, the homepage preview, sitemap, and RSS feed.
5. When ready, set **Status → Published**, save, then commit and push the content changes to GitHub. The next successful deployment publishes them. To remove a post from the website, change it back to Draft and deploy again.

Content is stored in `content/articles/*.mdoc`; uploaded images go in `public/writing/`. Keep an article's URL slug unchanged after publication. The date field controls display and ordering; it does **not** schedule future publication. Drafts stored in a public Git repository are visible in that repository even though the website does not serve them.

### Optional hosted editor

The local editor works without an account or additional service. Production `/keystatic` and its API return 404 until GitHub authentication is configured. Local draft previews also return 404 in production.

For editing from the deployed website, follow [Keystatic's GitHub mode setup](https://keystatic.com/docs/github-mode), restrict the GitHub App to `prodev1996/portfolio`, and configure these variables in the hosting environment:

- `NEXT_PUBLIC_KEYSTATIC_GITHUB_APP_SLUG`
- `KEYSTATIC_GITHUB_CLIENT_ID`
- `KEYSTATIC_GITHUB_CLIENT_SECRET`
- `KEYSTATIC_SECRET`

Register the production callback URL described in that guide and redeploy after configuration. Keep credentials in environment settings, never in Git. GitHub mode saves to the repository; publishing still requires a successful deployment of the production branch. Hosted draft preview is not implemented.

Article pages include reading times, heading navigation, copyable code, canonical metadata, and BlogPosting structured data. The feed is `/writing/feed.xml`. Styles are in `app/writing.css`; schema and editor configuration are in `keystatic.config.ts`.

## Interaction and accessibility

System-aware light/dark themes, visible keyboard focus, skip navigation, an Escape-dismissable mobile menu, native touch scrolling, reduced-motion support, responsive images, and a printable résumé. Project filters announce their results.

The contact form preserves the existing EmailJS integration and field names. Delivery uses the existing public service configuration. Browser verification checks validation without sending a real message.

Avoid using untrusted glob patterns in those tools and revisit the advisory when an upstream fix ships.
